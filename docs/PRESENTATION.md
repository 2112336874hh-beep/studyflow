# 발표 순서와 시연 안내

## 1. 소개 (약 30초)

“여러 강의의 과제와 복습 일정을 한눈에 관리하기 위해 StudyFlow를 만들었습니다. 기존 실습 과제를 제출하지 않아 이번 프로젝트는 처음부터 만든 앱입니다.”

## 2. PRD (약 30초)

대상은 여러 과목을 수강하는 대학생입니다. 핵심 요구사항은 할 일 추가, 마감일, 완료 표시, 진행률입니다. 로그인 없이 바로 사용할 수 있게 브라우저 저장 방식을 선택했습니다.

## 3. 앱 시연 (약 90초)

1. 최초 예시와 네 개 통계 카드를 보여 줍니다.
2. “중간 보고서 작성”을 추가하고 과목·날짜·우선순위를 지정합니다.
3. 해당 항목을 수정한 뒤 완료 표시합니다. 완료율 변화를 설명합니다.
4. 과목 검색과 완료 필터를 보여 줍니다.
5. 새로고침하여 저장 유지와 JSON 백업 기능을 설명합니다.

## 4. Todo 변경 (약 45초)

README 표로 최초 계획과 최종 구현을 비교합니다. 과목·우선순위·메모, 수정, 검색, JSON 백업이 추가된 이유를 설명합니다. 개발 중 설계 판단과 실제 테스트 결과를 구분해서 말합니다.

## 5. 스킬과 배운 점 (약 45초)

Sites 스킬로 정적 웹 앱 제작·미리보기 흐름을 참고했습니다. GitHub 연결을 확인할 때 Plugin Management를 사용했고 브라우저 확인에 Computer Use 지침을 참고했습니다. 각 원문 SKILL.md는 저장소에 포함했습니다. 직접 만든 스킬은 없습니다.

AI가 작성한 결과를 그대로 신뢰하지 않고 실제 입력과 통계 변화를 확인하는 것이 필요했습니다. 작성자는 발표 전에 본인이 코드를 읽고 설명할 수 있도록 준비합니다.

## 6. 한계 (약 20초)

현재 저장은 브라우저 단위이며 로그인·기기 동기화·푸시 알림이 없습니다. 이후 계정별 동기화와 캘린더 연동을 추가할 수 있습니다.
